# JSON Schema Manager (Angular 20)

![CI](https://github.com/LuigiElleBalotta/json-schema-manager/actions/workflows/ci.yml/badge.svg)
![Deploy Demo](https://github.com/LuigiElleBalotta/json-schema-manager/actions/workflows/deploy-demo.yml/badge.svg)
![Release](https://github.com/LuigiElleBalotta/json-schema-manager/actions/workflows/release.yml/badge.svg)
![npm](https://img.shields.io/npm/v/@elle96/ng-json-schema-manager)

An Angular 20 library that renders any JSON Schema into a fully reactive Angular form. Supports legacy drafts (draft‑04/06/07) and modern drafts (2019‑09/2020‑12). If `$schema` is absent the library infers a best‑effort draft. Styled exclusively with Tailwind utility classes (v3 and v4 compatible). Includes dark mode support.

## Tailwind setup

The library ships **no CSS** — it uses only Tailwind utility classes that must be generated by your app's Tailwind build.

### Tailwind v3

```js
// tailwind.config.js
module.exports = {
  darkMode: 'class',
  content: [
    './src/**/*.{html,ts}',
    './node_modules/@elle96/ng-json-schema-manager/**/*.{js,mjs}',
  ],
};
```

### Tailwind v4 (PostCSS)

```json
// postcss.config.json
{
  "plugins": {
    "@tailwindcss/postcss": {},
    "autoprefixer": {}
  }
}
```

```css
/* styles.css */
@import "tailwindcss";

/* Required for class-based dark mode in Tailwind v4 */
@custom-variant dark (&:where(.dark, .dark *));
```

> In Tailwind v4 `darkMode: 'class'` in the config has no effect — use `@custom-variant` in CSS instead.

## Usage — standalone component

```ts
import { Component } from '@angular/core';
import { JsonSchemaFormComponent, JsonSchema } from '@elle96/ng-json-schema-manager';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [JsonSchemaFormComponent],
  template: `
    <jsm-json-schema-form
      [schema]="schema"
      [data]="initialData"
      [allowAdditionalProperties]="false"
      (formReady)="form = $event"
      (schemaReady)="onSchemaReady($event)"
      (valueChange)="value = $event"
    ></jsm-json-schema-form>
  `,
})
export class AppComponent {
  form: any;
  value: unknown;
  initialData = { firstName: 'Sara', age: 31 };

  schema: JsonSchema = {
    title: 'Profile',
    type: 'object',
    required: ['firstName'],
    properties: {
      firstName: { type: 'string', minLength: 2 },
      age:       { type: 'integer', minimum: 1 },
      role:      { type: 'string', enum: ['Admin', 'User'] },
    },
  };

  onSchemaReady(schema: JsonSchema) {
    console.log('resolved schema', schema);
  }
}
```

import { NgModule } from '@angular/core';

## `jsm-json-schema-form` API

### Inputs

| Input | Type | Default | Description |
|---|---|---|---|
| `schema` | `JsonSchema` | **required** | The JSON Schema to render. |
| `data` | `unknown` | `undefined` | Initial form data. Merged with schema defaults. |
| `value` | `unknown` | `undefined` | Alias for `data`. |
| `allowAdditionalProperties` | `boolean` | `false` | When `true`, shows an "Add property" UI on every object node that permits extra keys (`additionalProperties !== false`). When `false` (default) the UI is never shown, regardless of the schema. |

### Outputs

| Output | Payload | Description |
|---|---|---|
| `formReady` | `FormGroup` | Emitted once the reactive form is built. Use this to access the `FormGroup` instance directly. |
| `schemaReady` | `JsonSchema` | Emitted once all `$ref` (local and external) are resolved. The payload is the fully resolved schema. Use it to show/hide a loading indicator. |
| `valueChange` | `unknown` | Emitted on every form value change. The payload mirrors the schema structure. |

### Public methods

| Method | Returns | Description |
|---|---|---|
| `validate()` | `boolean` | Marks all fields as touched, forces error display across the entire form, and returns `true` if the form is valid. Call this from an external **Save** or **Submit** button to show all validation errors at once without requiring the user to touch every field. |

**Example — external save button:**

```ts
// app.component.ts
@ViewChild(JsonSchemaFormComponent) schemaForm!: JsonSchemaFormComponent;

save(): void {
  const isValid = this.schemaForm.validate();
  if (isValid) {
    // proceed with save
  }
}
```

```html
<!-- app.component.html -->
<jsm-json-schema-form
  [schema]="schema"
  [data]="data"
  (formReady)="form = $event"
></jsm-json-schema-form>

<button type="button" (click)="save()">Save</button>
```

## Supported JSON Schema keywords

### Primitive constraints (UI + Angular validators)
| Keyword | Applies to |
|---|---|
| `type` | All — drives input type (`text`, `number`, `email`, `date`, `datetime-local`, `password`, `checkbox`) |
| `enum` | Any — renders a `<select>` |
| `const` | Any — renders a disabled field pre-filled with the constant |
| `default` | Any — used as initial value when no `data` is provided |
| `format` | `string` — `email`, `date`, `time`, `date-time`, `password`, `textarea` |
| `minLength` / `maxLength` | `string` |
| `pattern` | `string` |
| `minimum` / `maximum` | `number`, `integer` |
| `exclusiveMinimum` / `exclusiveMaximum` | `number`, `integer` |
| `multipleOf` | `number`, `integer` |
| `readOnly` | Any — disables the control |
| `writeOnly` | Any — shown as a badge |
| `deprecated` | Any — shown as an amber badge |
| `nullable` | Any — shown as a badge |
| `examples` | Any — shown as hint text below the field |
| `contentMediaType` / `contentEncoding` | `string` — shown as hint text |

### Object keywords
| Keyword | Behaviour |
|---|---|
| `properties` | Each property renders as a child node. Simple primitives go in a 2-column grid; objects/arrays/combinators span full width. |
| `required` | Marks fields with `*` and adds `Validators.required`. |
| `patternProperties` | Dynamic keys matching the pattern can be added when `allowAdditionalProperties` is enabled. |
| `additionalProperties` | When `true` or an object schema, extra keys can be added (requires `allowAdditionalProperties` input). When `false`, no extra keys allowed. |
| `propertyNames` | Validates the name of dynamically added keys. |
| `dependentRequired` | Adds required fields dynamically when a key is present. |
| `dependentSchemas` | Merges additional schema when a key is present. |
| `dependencies` (draft-04/07) | Array form adds required fields; schema form merges schemas. |
| `minProperties` / `maxProperties` | Validated via Angular validators. |

### Array keywords
| Keyword | Behaviour |
|---|---|
| `items` | Schema for all items. |
| `prefixItems` | Tuple — each index uses its own schema. |
| `additionalItems` | Schema for items beyond the tuple. |
| `unevaluatedItems` | Schema for items not covered by `prefixItems`. |
| `contains` | Shows a hint; validated by Ajv. |
| `minItems` / `maxItems` | Validated; "Add item" button is disabled when `maxItems` is reached. |
| `uniqueItems` | Validated by Angular validator. |
| `minContains` / `maxContains` | Shown in the contains hint. |

### Composition keywords
| Keyword | UI behaviour |
|---|---|
| `oneOf` | Renders a **tab bar**. Switching tabs rebuilds the subtree with the selected variant's schema. |
| `anyOf` | Renders **pill toggles** (checkboxes). Multiple variants can be active; schemas are merged. |
| `allOf` | Merges all sub-schemas and renders each section with a left accent border. |
| `not` | Shown as a "Not constraint" badge; validated by Ajv. |

### Conditional keywords
| Keyword | Behaviour |
|---|---|
| `if` / `then` / `else` | Evaluated live against the current node value. The matching branch is merged into the rendered schema. |

### Reference keywords
| Keyword | Behaviour |
|---|---|
| `$ref` | Resolved before rendering. Local refs (`#/definitions/…`, `#/$defs/…`) and external URLs are both supported. |
| `$defs` / `definitions` | Used as the local ref store. |
| `$id` | Sets the base URL for resolving relative external refs. |

## Validation

Validation runs on two layers:

1. **Angular validators** — built synchronously from the schema keywords listed above. Errors appear below each field once the control is `dirty` or `touched` (i.e. after the user has interacted with it).
2. **Ajv** — runs on the full form value on every change. Errors are mapped to JSON Pointer paths (`/firstName`, `/contact/email`, etc.) and displayed inline next to the relevant field.

Error display rules:
- Errors are shown on a field as soon as it is **touched** (focus + blur) or **dirty** (value changed).
- Calling `validate()` on the component forces all errors to show immediately, regardless of touched/dirty state — useful for a Save button that should surface all problems at once.

Draft detection order:
1. Read `$schema` URI.
2. Match against known draft URIs (draft-04, draft-06, draft-07, 2019-09, 2020-12).
3. If absent or unrecognised, fall back to draft-07 behaviour.

---

## Layout rules

The renderer follows a consistent layout strategy:

- **Everything is in a single column by default.**
- Inside an `object`, child fields are classified:
  - **Simple** (`string`, `number`, `integer`, `boolean`, `enum`) → placed in a responsive 2-column grid (`sm:grid-cols-2`).
  - **Complex** (`object`, `array`, `oneOf`, `anyOf`, `allOf`) → always full width (`col-span-2`).
- `array` items are always full width, stacked vertically.
- Combinator blocks (`oneOf`, `anyOf`, `allOf`) are always full width.

## Architecture — for AI agents and contributors

This section describes the internal structure so that an AI agent or new contributor can understand, extend, or re-implement the library without reading every file.

### File map

```
projects/ng-json-schema-form/src/
├── public-api.ts                        # Barrel — everything exported from here
└── lib/
    ├── types.ts                         # JsonSchema interface and related types
    ├── json-schema-form.component.ts    # Public entry-point component <jsm-json-schema-form>
    ├── json-schema-node.component.ts    # Recursive renderer <jsm-schema-node>
    ├── json-schema-form.service.ts      # Builds the Angular reactive form tree
    ├── json-schema-resolver.service.ts  # Resolves $ref (local + external fetch)
    ├── json-schema-validation.service.ts# Ajv wrapper — draft detection + validate()
    └── json-schema-form.module.ts       # NgModule wrapper for non-standalone usage
```

### Data flow

```
[schema input]
      │
      ▼
JsonSchemaResolverService.resolve()   ← fetches external $ref, inlines them
      │
      ▼
JsonSchemaFormService.buildControl()  ← walks the resolved schema recursively,
      │                                  returns FormGroup / FormArray / FormControl
      ▼
<jsm-json-schema-form>                ← holds the root FormGroup, wires valueChanges
      │                                  to JsonSchemaValidationService.validate()
      ▼
<jsm-schema-node> (recursive)         ← reads schema + control, renders the correct
                                         input widget, passes errorsMap down
```

### `JsonSchema` type (`types.ts`)

The `JsonSchema` interface extends four partial interfaces:

- `JsonSchemaBase` — scalar keywords (`type`, `title`, `description`, `format`, constraints…)
- `JsonSchemaObject` — object keywords (`properties`, `required`, `additionalProperties`…)
- `JsonSchemaArray` — array keywords (`items`, `prefixItems`, `contains`…)
- `JsonSchemaCombinators` — composition keywords (`allOf`, `anyOf`, `oneOf`, `if/then/else`…)

Plus top-level `$defs` / `definitions`.

### `JsonSchemaFormService` (`json-schema-form.service.ts`)

Key method: `buildControl(schema, value?, required?): AbstractControl`

- Calls `resolveType(schema)` to determine `'object' | 'array' | 'string' | 'number' | …`
- For `object`: creates a `FormGroup`, iterates `properties`, recurses for each child. Also handles dynamic keys from `value` that are not in `properties`.
- For `array`: creates a `FormArray`, pre-populates from `value` or `minItems`.
- For primitives: creates a `FormControl` with initial value from `value ?? schema.default ?? schema.const ?? null`.
- Attaches Angular `ValidatorFn[]` built from schema constraints.
- Disables controls for `readOnly: true` or `const`.

`resolveType(schema)` priority: `enum` → `oneOf[0]` → `anyOf[0]` → `allOf[0]` → `schema.type` → infer from keywords → `'string'`.

`resolveDynamicSchema(schema, key)`: finds the schema for a dynamic key by testing `patternProperties` regexes, then falling back to `additionalProperties`.

### `JsonSchemaResolverService` (`json-schema-resolver.service.ts`)

`resolve(schema, baseUrl?): Promise<JsonSchema>`

- Walks the schema tree looking for `$ref` strings.
- Local refs (`#/…`) are resolved against `$defs` / `definitions` on the root schema.
- External refs (absolute URLs or relative to `$id`) are fetched with `fetch()` and inlined.
- Returns a new schema object with all `$ref` replaced by their resolved values.

### `JsonSchemaValidationService` (`json-schema-validation.service.ts`)

`validate(schema, value): ErrorObject[]`

- Detects the draft from `schema.$schema`.
- Instantiates the correct Ajv version (Ajv draft-04, Ajv 2019, Ajv 2020, or default Ajv).
- Adds `ajv-formats` for format validation.
- Returns Ajv `ErrorObject[]`. Each error has `instancePath` (JSON Pointer) and `message`.

### `JsonSchemaNodeComponent` (`json-schema-node.component.ts`)

Inputs:
| Input | Type | Description |
|---|---|---|
| `schema` | `JsonSchema` | The schema for this node. |
| `control` | `AbstractControl` | The corresponding reactive control. |
| `label` | `string` | Display name (falls back to `schema.title`). |
| `required` | `boolean` | Whether this field is required by its parent. |
| `path` | `string` | JSON Pointer path to this node (e.g. `/contact/email`). Used to look up errors in `errorsMap`. |
| `errorsMap` | `Map<string, string[]>` | Map of JSON Pointer → error messages, produced by Ajv. |
| `parent` | `FormGroup \| FormArray` | Parent control, needed to replace the control on `oneOf`/`anyOf` change. |
| `controlKey` | `string \| number` | Key in the parent, needed for the same reason. |
| `allowAdditionalProperties` | `boolean` | Passed down from `jsm-json-schema-form`. Controls visibility of "Add property" UI. |
| `showErrors` | `boolean` | When `true`, errors are shown on all fields regardless of touched/dirty state. Set automatically by `validate()`. |

`nodeKind` getter determines which template branch to render:
`'oneOf' | 'anyOf' | 'allOf' | 'object' | 'array' | 'primitive'`

`effectiveSchema` getter applies `allOf` merging, `if/then/else` evaluation, and `dependencies`/`dependentSchemas` merging on top of the raw `schema` input.

`isSimpleChild(key)`: returns `true` if the child schema resolves to a primitive type (not object/array/combinator). Used to decide 1-col vs 2-col grid placement.

`canAddProperty`: returns `true` only when `allowAdditionalProperties` is `true` **and** the schema does not have `additionalProperties: false`.

When `oneOf` or `anyOf` selection changes, `replaceControl()` rebuilds the subtree control and either updates the parent directly or emits `controlReplaced` for the root case.

### `JsonSchemaFormComponent` (`json-schema-form.component.ts`)

Selector: `jsm-json-schema-form`

Lifecycle:
1. `ngOnChanges` → calls `buildForm()` when `schema` changes. When only `value`/`data` changes and the form already exists, patches values with `patchValue` without rebuilding (preserves focus and touched/dirty state).
2. `buildForm()` → resolves schema → builds control → emits `formReady` and `schemaReady` → subscribes to `valueChanges` → calls `updateErrors()` on every change.
3. `updateErrors()` → normalizes numeric string values to numbers (coercion for `<input type="number">`) → runs Ajv validation → rebuilds `errorsMap` → passes it to the root `jsm-schema-node`.

Public method: `validate(): boolean` — marks all controls as touched, sets `showErrors = true` on all nodes, forces change detection, and returns `form.valid`.

### Styling conventions

- All styles are Tailwind utility classes — no component `styles` array, no CSS files.
- Dark mode uses `dark:` variants. Activated by the `dark` class on `<html>`.
- In Tailwind v4, `@custom-variant dark (&:where(.dark, .dark *))` must be declared in the app's global CSS.
- Error states: `border-red-300 bg-red-50` (light) / `border-red-700 bg-red-900/20` (dark), shown only when `controlAsFormControl.dirty`.
- Focus states: `focus:border-indigo-400 focus:ring-2 focus:ring-indigo-100` (light) / `dark:focus:ring-indigo-900/40` (dark).
- Object fieldsets get `focus-within:border-indigo-300 focus-within:ring-2` to highlight the active group.
